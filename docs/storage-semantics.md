# 数据与兼容边界

物理表包括 meta、collections、versions、commits、receipts、index_defs、index_values、pins、consumers、read_views。versions 的主键为集合、键、修订；body 的 SQL NULL 表示删除，JSON null 只能作为文档字段。collections 保存当前模式；index_values 是当前 head 的投影。commits 保存完整的操作序列；receipts 保存不受历史回收影响的请求摘要与结果。read_views 每行保存名称、修订与规范化后的集合名列表。幂等键不能被不同操作复用，回放不重新执行前置条件。

floor 是仍可读取的最早修订，不代表每条物理版本的最小修订；每个键在 floor 之前的最后版本可能是构造 floor 读视图的基准，必须保留。commits 仅需保存大于 floor 的提交，消费者从自己的 ack 之后读取。pin、消费者位置与具名读视图的修订不能低于现存 floor；创建视图时若指定的修订已被回收，按 `SnapshotTooOld` 拒绝。

具名读视图是名称到「修订 + 集合组」的持久映射，与 pin 同属目录元数据而非文档版本。名称在数据库范围内唯一，遵循与集合、索引、pin 相同的小写名称格式；重名创建失败且不修改原视图。视图只登记名称、修订和集合名，不复制文档内容，也不冻结模式，因此不会推进 head 或 logical fingerprint。读取时名称在同一 SQLite 读事务内解析，解析到的修订与随后读到的可见快照一致，不会出现名称已更新而数据未切换的撕裂。视图成员集合必须在登记时存在；之后新增的集合并不会自动成为成员，成员变化需要新的视图名。集合后来演进模式（包括新增字段）不会改变既有视图，历史文档仍按原 JSON 解释。删除视图仅移除该名称对回收水位的阻塞；同修订的其它视图、pin 或消费者仍各自阻塞，回收水位只有在所有阻塞都释放后才可能越过该修订。

模式包含 fields、required、additional，支持点路径类型；additional=false 限制顶层未知根字段，不递归禁止已声明对象中的子字段。字段不允许 null，除非该字段未声明类型；缺失可通过 required 控制。integer 排除 bool，number 接受整数及有限浮点。JSON 对象不允许非字符串键；浮点必须有限。索引忽略缺失字段与对象/数组，空值作为可索引标量，数值 1 和 1.0 共用索引值，true 与 1 不共用。

游标携带数据库身份、谓词摘要、读版本和最后键，并由数据库私有密钥签名。它不是权限凭据，不冻结模式，也不是保留租约。使用具名读视图分页时，谓词摘要还绑定视图名，继续分页必须带上同一 `view`；只给 `revision` 或换视图都会因摘要不符被拒。需要稳定的长时间读取，调用者自行管理具名保留点或具名读视图。

副本包是内部可信通道数据，校验和只用于检测传输损坏。正常备份恢复新主库保留逻辑内容而更换身份；副本初始化保留上游身份。备份文件包含 read_views 行，因此恢复出的数据库保留视图名称及其修订，同名读取仍命中同一时刻——恢复不重置或重解释视图。restore 清理 pin 与消费者这些绑定原主机的租约，但不清理视图，因为视图是数据库的逻辑内容。复制通道只传文档、模式与索引，不迁移视图名称；副本上的视图是本地元数据，可独立创建、读取和删除。分段追赶未完成时暂不提供当前索引，避免最新唯一约束错误约束中间历史视图。目录 epoch 可在没有文档提交时前进，最终空提交包仍能传递新的模式与索引。
